## Description

Design the machine breakdown triggers and emergency repair minigames.
Reinforces the manic goblin tinkerer fantasy by requiring quick, tactile maintenance during active sieges.

> [!NOTE]
> This feature is currently in the conceptual design phase. Mechanics and triggers require full definition before implementation.

## Core Objectives

1. **Breakdown Triggers and Instability:**
   - Define what causes machine faults (for example: excessive heat, high firing rates, or time intervals).
   - Establish breakdown symptoms (for example: jammed hopper, leaky mana pipe, loose bumper bolts).

2. **Minigame Interactions:**
   - Design fast, tactile repair actions (for example: rapid clicks to tape a pipe, quick mouse flick to unjam a valve, timing press to tighten a bolt).
   - Ensure minigames do not overwhelm active board management or hopper steering.

3. **Penalties and Rewards:**
   - Define the consequence of unresolved breakdowns (for example: reduced hopper drop speed, lower cannon damage, temporary power outage).
   - Define the reward for perfect repairs (for example: instant mana burst or short overclock boost).

## Acceptance Criteria

- [ ] Complete design document detailing at least 3 breakdown types and repair interactions.
- [ ] UI wireframes or interaction specifications documented for mouse/keyboard inputs.
- [ ] User approval on repair flow before code implementation.
